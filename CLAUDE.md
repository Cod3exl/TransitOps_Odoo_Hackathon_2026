# TransitOps

Smart transport operations platform — 8-hour hackathon build, 3-person team, one shared monorepo.

## Stack

- **Server**: `server/` — Node.js, Express 4, TypeScript, Prisma 5, PostgreSQL, JWT auth (`jsonwebtoken` + `bcryptjs`)
- **Client**: `client/` — Vite, React 19, TypeScript, Tailwind CSS v4 (plain utility classes — no shadcn/Radix; shared primitives live in `src/components/ui.tsx`), TanStack Query, React Hook Form + Zod, Recharts
- No BaaS (no Supabase/Firebase). Auth, RBAC, and business-rule enforcement are all hand-written — not auto-generated by the database.
- Dependency versions are pinned (not `latest`) across the board — this avoided a cluster of breaking changes (Prisma 7's driver-adapter requirement, TypeScript 7 removing `moduleResolution: node`, Express 5's stricter param typing) hit during an earlier from-scratch attempt at this same stack. Don't casually bump majors mid-hackathon.

## Business rules (non-negotiable)

- Registration numbers and license numbers are globally unique.
- Retired or in-shop vehicles never appear in dispatch selection.
- Drivers with expired licenses or `suspended` status can't be assigned to trips.
- A vehicle or driver already `on_trip` can't be assigned to another trip.
- Cargo weight can't exceed the vehicle's max load capacity.
- Dispatch → vehicle and driver both become `on_trip`. Complete → both become `available`, vehicle odometer increments. Cancel (from dispatched) → both restored to `available`.
- Opening a maintenance record → vehicle becomes `in_shop`. Closing it → vehicle becomes `available` unless it's `retired`.

All of these are enforced in `services/*.ts`, wrapped in `prisma.$transaction`, never trusted from client input alone. A judge testing the API directly (not just the UI) should still be blocked by every rule above.

## Git & commits — human only, no exceptions

This is a hackathon and every commit needs to be traceable to the team member who made it, with zero ambiguity for evaluation. **Claude Code must never run `git commit`, `git push`, or any command that finalizes a commit or opens a PR — in this or any session, no matter how small the change.**

What to do instead:
- Make the code changes, run the build/tests to confirm they work, then stop.
- Report what changed and suggest a commit message in the `type: description` format below.
- Leave `git add`, `git commit`, and `git push` entirely to the human, typed by hand in their own terminal.

If a message says "commit this" or "push this," treat it as "prepare this for me to commit" — stage nothing, commit nothing, just confirm the changes are ready and hand back a suggested message. This rule has no exceptions for convenience or speed.

## Conventions

- Commit format: `type: short description` — `feat`, `fix`, `chore`, `polish`, or `docs`. One commit per completed task, roughly one per hour per person. **The human runs this command, not Claude Code.**
- Every mutating route requires both `authenticate` and `authorize(...roles)` middleware.
- Validate request bodies with Zod in the route handler before they reach the service layer.
- Money, weight, and distance fields are `Float` in Prisma.
- `.env` is gitignored. `DATABASE_URL` and `JWT_SECRET` never get committed.

## Don't

- Don't add a BaaS platform (Supabase, Firebase, etc.) — auth and business rules must be hand-written in this codebase.
- Don't put business-rule logic in a React component — it belongs in a `services/*.ts` transaction so it's enforced server-side.
- Don't touch another team member's owned files listed above without asking first.
- Don't run `git commit`, `git push`, or open a PR — ever. See the git section above.
